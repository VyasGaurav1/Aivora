# Decisions

- AIVORA and com.chronoit.aivora are permanent identifiers, enforced in Gradle, manifest label, source packages and project instructions.
- Configurable display/wake names default to Aivora. A saved name is not evidence of wake-model enrollment.
- DataStore migrates the initial assistant_identity SharedPreferences. Filenames and Keystore aliases remain independent of assistant names. Room v1 exports its schema and does not permit destructive migration.
- Build uses locally installed JDK 21, Gradle 9.3.1, AGP 9.1.1, Compose compiler 2.2.10 and pinned UI dependencies. Runtime has no internet permission.
- Memory fields use record-bound AES-GCM. Room v2 FTS stores keyed HMAC tokens rather than plaintext words; filename prefixes allow bounded partial matching. This exposes token equality/frequency, not full searchable encryption. Legacy memory is indexed locally after migration. Private-mode changes serialize with new learning commits.
- Android system UI handoffs report REQUIRES_USER_INTERACTION, not completed effects. Unverified media changes report PARTIAL. Sensitive sharing requires device authentication followed by exact-plan confirmation.
- Explicit phrases store encrypted command text and provenance, never authentication, confirmation or executor tokens. Every invocation re-parses against current installed apps, validates and dispatches a fresh plan through policy. Context-dependent contact/file references are rejected during teaching until durable reference semantics exist.
- sherpa-onnx 2.0.1 is isolated behind SpeechToTextEngine; model assets are bundled at an immutable revision with SHA-256 inventory in docs/MODELS.lock.json. Native arm64 load segments inspected at 16 KB alignment. Broader native/platform validation remains pending.
- Bundled VITS VCTK int8 provides local speech without an external TTS engine. JNI callback uses an explicit typed object and catches exceptions before returning across JNI; regression tests cover the original process-abort failure. Text normalization prevents native OOV logs from exposing unrecognized user words.
- Speaker enrollment uses device credential and stores embeddings only. Wake enrollment stores MFCC templates only. Atomic encrypted profile replacement keeps the previous wake active after a failed rename enrollment. Neither template matching nor embedding similarity is claimed to provide replay/liveness protection.
- VerifiedVoicePipeline verifies the command audio before STT and issues a one-use ten-second grant. User opt-in is separate from enrollment; model/action payloads cannot set command provenance. Sensitive plans require a platform credential result and then a new single-use confirmation token, with device lock rechecked at each action.
- [Android microphone foreground-service restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start) are respected: background wake starts from visible user interaction, declares microphone FGS permissions/type, has a persistent stop notification and does not silently restart after death. If selected as Assistant, it requests the system VoiceInteractionSession; otherwise notification handoff respects background activity restrictions.
- [RecognitionService](https://developer.android.com/reference/android/speech/RecognitionService) is backed only by bundled STT; provider results do not dispatch actions. Supplied 16 kHz mono PCM is bounded by duration, samples and descriptor lifetime. UI, provider and wake service share one physical microphone lease.

- Learned file references are explicitly scoped to an owner-selected project and bind to stable catalog IDs. No filename fallback occurs after access loss, deletion or revocation. Project selection is session-only; selecting another project clears pending choices and pronoun context. Corrections supersede the prior encrypted vocabulary record; private mode blocks saving through the same memory gate.

- Reminder definitions live in separate Room aivora_tasks.db, permanently independent of wake/assistant name. Text is AES-GCM bound to task ID. Pinned WorkManager 2.9.1 supports approximate persistent reminders; no exact-alarm privilege is added. Unique KEEP work prevents app-start recovery from replacing/canceling a running delivery. Active-only periodic recovery reconciles persisted definitions after enqueue gaps. Notification posting is checked before success is stored. A crash between posting and state commit may repost under the same notification tag; no exactly-once delivery claim. Private mode stops learning, while deliberately requested reminder definitions persist.

- Scheduled action payloads use a versioned strict typed codec, AES-GCM record binding, explicit fresh-owner-review authorization and NETWORK_NONE. Worker delivery never dispatches device actions. Review creates a fresh policy plan; execution revalidates action, due/cancellation state and target while sharing the scheduler mutex with cancellation. STARTED is committed before side effects, remains visible after interruption and cannot auto-retry. File content SHA-256 is checked at creation/review/execution with a 256 MiB bound, and named sharing recipients are uniquely resolved/bound; no immutable content snapshot guarantee. Recurring/automatic actions and other network policies remain future work. Notification notify() acceptance is asynchronous, so delivery waits up to 2 seconds for an active notification before committing success.


- Task conditions are immutable encrypted definitions, separate from transient Android observations. Defaults preserve earlier unconstrained reminders/actions during v1/v2-to-v3 migration. New encrypted action envelopes include the saved condition policy so missing/changed condition blobs cannot silently weaken them. WorkManager supplies wakeup constraints; AIVORA independently rechecks plugged charging state and validated network capabilities at delivery/review/execution, including after expensive target hashing. Validation uses capabilities from one network snapshot, not mixed metering state. These observations can change immediately afterward; external app reachability/completion is not inferred. Conditions do not enable connectivity.

- Recurring single-action schedules retain the initial target fingerprint and conditions and require fresh owner review for every due occurrence. Approval binds task ID plus exact dueAt, not just the action. Notification delivery does not advance an action's occurrence. Verified success or REQUIRES_USER_INTERACTION advances along the original interval; external completion is not inferred. Failures/PARTIAL pause the series; STARTED interruption cannot auto-retry. A clock rollback cannot reuse the handled dueAt. No automatic background-action authorization is implied by defining a series.

- Online tasks declare requiresNetwork separately from opening an app: opening YouTube alone may be useful offline, while search/video-link tasks require validation. Standard Android uses its internet controls, never an assumed silent toggle. Expiring synchronized pending-task state retains immutable actions and original provenance outside model payloads. Resume preserves the original execution registry so connectivity cannot bypass scheduled occurrence/target guards. Only foreground/unlocked resume is attempted; direct executor network recheck handles connection loss. Restoration is not attempted without known controllable state and verified task completion. YouTube outcomes remain REQUIRES_USER_INTERACTION with explicitly unverified playback.

- Spoken approval captures the existing confirmation identity before microphone input and consumes it once only for VERIFIED_VOICE. It cannot authorize a replacement plan or supply Android device authentication. A new command/cancel clears approval context. Full short plans are spoken before recording; long descriptions are never truncated into an approval prompt. One bounded reply capture avoids an uncontrolled listening loop. Full confirmation/authentication descriptions scroll in the UI.

- AuthenticationLaunchGate authorizes opening one real Android prompt only for an opted-in VERIFIED_VOICE request with matching token/plan/expiry. It never grants device authentication. MainActivity waits for RESUMED before launching and before processing a successful result into spoken review, cancels its signal on destruction, and serializes the API29 credential launcher so callbacks cannot be reassigned to newer requests. ViewModel success/failure handlers ignore tokens that no longer match the pending authentication. Typed requests retain manual authentication. Device credential authorization and exact-plan confirmation remain separate.

- Repeated foreground wake is an explicit runtime opt-in, separate from the background microphone service and persisted hands-free execution preference. ForegroundWakeLoop owns and cancels only its specific bounded wake capture; generation checks prevent an old stopped loop from disabling a replacement. Idle capture does not invoke the manual hook that can cancel owner work. After verified wake, a non-canceling readiness hook binds current approval before command capture. Normal voice requests/authentication/replies interrupt the capture while retaining opt-in; Stop/Cancel/enrollment/profile removal/opt-out/closure stop it. Shared-lease readiness and transient-busy handling allow foreground/background microphone handoff; no startup/reboot recording is added.

- Spoken selections use a dedicated capture-time VoiceChoiceGate, separate from action approval and authentication. Exact list identity/kind/count and one-use verified provenance prevent an old ordinal from selecting a newer list. Dialogue retains two-minute choice expiry and normal target rechecks. Three-entry readback pages preserve global numbers; page navigation does not select/execute or renew the deadline. Over-budget complete options require narrowing/on-screen review. Choice resolution retains existing schedule/condition/recurrence context, rather than routing through new-command initialization that could lose the schedule. The controller generic verifiedReply is shared by action reviews and choice readouts; it does not itself authorize actions.

- Wi-Fi uses a separate opt-in and medium-risk typed action; Android Settings launches its user-visible Internet panel. Only the known System UI Internet/Wi-Fi/Done IDs and exact observed label booleans can be acted on, with no gestures or general Settings fallback. Full-page root refusal is respected; AIVORA remains a non-accessibility-tool service. Radio state is verified independently through WifiManager and does not establish internet. The Done state is awaited after the radio broadcast, then the existing AIVORA activity is reused. The approved original task retains its registry/provenance and resumes after helper completion only when validated connectivity and foreground/unlocked state hold. The emulator network lacks internet, so the explicit probe separates radio acceptance from network-resume acceptance using harness-restored mobile data. No production mobile-data control or automatic restoration is implied.

- Connection replies require their own capture-time binding, distinct from action confirmations and numbered choices. NetworkReview retains the original immutable plan/source/deadline outside serialized model payloads. Stale replies reject before canceling newer command work; ordinary new commands invalidate pending connectivity at submission rather than after joining old work. Auto readback joins an already-presented question task and never turns connection permission into action execution/authentication. Typed foreground replies remain explicit owner input and the UI shows the full task. Physical acoustic approval is separate from injected-grant routing tests.

- Mobile-data is a separate default-off high-risk action because carrier charges and SIM selection require stronger review. Bind the complete active single default subscription using public metadata/readiness, recheck before clicks, and verify per-subscription user setting independently of network validation. Unknown controls/subscriptions fail closed; no privileged setters, automatic restoration or subscriber secrets. Emulator authentication injection is routing evidence only.

- Owner clarified Android11+ broad device support. minSdk30 is permanent baseline unless the owner changes it; models must not be installation allowlists. Physical POCO/OPPO priorities do not substitute for API/OEM capability testing.

- Android11 baseline follow-up: obsolete API29 credential-activity branches and callback state were removed. Enrollment and action authentication now always use the supported DEVICE_CREDENTIAL BiometricPrompt path. Historical API29 checkpoint references above are superseded; physical positive/canceled credential acceptance remains pending.

- Payment review uses explicit complete merchant-link fields and exact paise, never inferred merchant identity/codes/references. CRITICAL policy and fresh Android authentication/confirmation gate an explicit-app URI request. No callback/notification is trusted as settlement. Core retains no INTERNET permission/backend/bank credentials. The current stage does not establish consumer P2P or PSP acceptance; merchant references are not reusable routines/schedules. See docs/PAYMENT_HANDOFF_DESIGN.md.

- API30 Internet Connectivity uses a bounded legacy Settings adapter, with Settings event scope added only on that SDK. The actual service tree is the selector authority, not the fuller UIAutomator dump. Require exact heading/row/hierarchy, unique label/switch, fresh radio/window/lock/opt-in and known dismissal; keep newer SystemUI behavior and non-tool/no-gesture constraints. Native probes establish radio changes and return only, not physical speech or internet.

- API30 mobile-data selection additionally requires an exact same-row SIM summary bound to independently read default-subscription metadata; a generic Mobile data title alone is insufficient. The known API30 direct-off panel does not authorize unknown dialogs. Shared service helpers select only the SDK-specific known Internet panel; newer exact SystemUI warning handling stays separate.

- Spoken reviews use shared complete action descriptions and a bounded1200character full prompt, without truncation or authority deadline renewal. Speech interruption/refusal is cancellation, and reply capture requires current identity/deadline after successful output. Native PCM acceptance is not proof of owner hearing, acoustic identity or payment approval.

- Payment speech uses explicit reversible character spelling for supported printable ASCII and exact rupees/hundredths, without changing transmitted request data. Missing lexicon words are avoided with known semantic currency wording. Unsupported scripts and oversized expanded review fail to full UI review. Model synthesis/normalization evidence is separate from actual pronunciation/comprehension or authenticated payment completion.

- Direct calling is separate default-off HIGH-risk authority. Bind canonical recipient and public caller SIM metadata before review; use enabled opaque Telecom account mapping without subscriber-number/account-detail access. Recheck active call/roaming/lock/foreground/contact/account before requesting, and return a request/handoff status only. Native tests are explicit known-emulator fixtures with injected authentication, never real-person calls or carrier-connection evidence.

- Direct-call eligibility is a pure proposal-stage binding. Ineligible calls preserve original dialer semantics and receive their own exact review; execution-time failures of an approved PlaceCall never silently downgrade or retry. Recheck recipient after settings suspension. Native named-contact provider mutation is independent evidence from mocked policy tests.

- Speakerphone is explicit per-call metadata, never a global default or an implicit route change. Preserve intent through choices, records and review; omit the Telecom extra for default audio. Old codec records remain canonical; new true-intent tags avoid a schema migration. Report requests separately from actual routing/physical audibility.
