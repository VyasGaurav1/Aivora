# Known limitations

7 November five-priority checkpoint supersedes earlier interruption/routing notes: wake-word barge-in is implemented and POCO-tested, including an own-wake-name self-echo check. Arbitrary overlapping commands without a wake phrase remain unsupported. Echo cancellation/wake accuracy varies by hardware. Local corrections match normalized questions and are attributed to the user, not externally verified facts; model weights are not trained. Follow-ups and saved-memory readbacks stay local. Exact-alarm access improves reminder timing but does not remove Doze quotas/OEM restrictions or the first-unlock requirement after reboot. Screen-off/battery-saver and real-reboot speech checks passed; these are not proof of prolonged unattended reliability. New grounded web summaries pass reviewed fixtures; factual correctness across arbitrary topics remains unproven. See docs/FIVE_PRIORITIES.md.


7 November local-memory revision: explicit user consent continues Gnani live speech and explicit Brave questions. Saved-memory replay, fact/history readbacks and scheduled reminder speech now use offline synthesis; stored history/feedback are not included in cloud requests. Recent conversation history is bounded to 80 encrypted text pairs, not unlimited storage or ambient recording. Explicit facts are separate. Feedback storage and speech-speed preferences are not reinforcement training; no model weights are updated. Human wake accuracy and prolonged OEM reliability remain unproven despite the five passing targeted device checks. API/key failures and Android force-stop still need user correction/reopening.


7 November voice checkpoint: spoken-reminder and grounded-summary playback pass on the POCO; seven device checks and 236 JVM tests pass. Two live wake-to-panel cycles were observed. Wake capture pauses during AIVORA's own speech; barge-in is not implemented. Android/MIUI force-stop or cleanup can stop listening until AIVORA is opened again. Reminder timing remains approximate and speech waits for an active conversation to finish. A separately provisioned, hash-verified 409.1 MiB Qwen model is required for local web summaries; the APK excludes those weights and no model downloader is implemented. Summary grounding checks are heuristics, not proof of factual accuracy across all questions. The POCO assistant-role test harness cannot reassign roles inside instrumentation without killing its target; this is reported separately from live-app evidence.

Current first-release checkpoint (5 November 2026): reminder notification delivery and a saved-key Brave web result have passed physical-device tests; alarm creation was confirmed by the user. Full spoken regression, alarm ringing and broad OEM/battery acceptance remain pending. The current Brave key lacks the Answers plan, so AIVORA speaks clearly labeled Web Search excerpts. A Gnani key makes cloud speech primary and requires internet/credits. Phone speech fallback may emit system tones. Speech supports ten Gnani languages; reminder/alarm intent parsing currently uses English. Historical limitations below may describe older checkpoints.

- Typed YouTube title/video-link requests and task-driven connectivity policy are implemented, with standard Android internet-panel handoff and one-minute foreground/unlocked resume. The emulator client can require an update; a foreground YouTube activity proves only app handoff. Search-result selection, compatible-device playback acceptance, arbitrary video browsing and complete voice UI control remain unfinished. Existing-video play/pause uses authorized media sessions with reported-state verification, plus a scoped accessibility fallback; the emulator has not proven positive playback. Core AIVORA still has no INTERNET permission. Silent connectivity activation, complete prior mobile-data-state capture and automatic restoration require an implemented privilege bridge and are not currently available. Transient online tasks expire instead of persisting after process death.

- Full offline assistant specification is incomplete. Local reasoning, messaging/payment automation and the privileged bridge remain unimplemented. The persistent scheduler supports one-time/recurring reminders and one-time/recurring single typed actions requiring fresh owner review for each occurrence, with charging/validated-network/unmetered-network conditions. Automatic background actions, exact alarms, recurring multi-action plans and broader event triggers remain unfinished. WorkManager delivery can be delayed by Android. An actual API 35 emulator reboot and notification-denial/restoration passed separate two-phase reminder probes; physical/OEM recovery, force-stop, network-transition and long-duration timing tests remain pending. Completed/canceled task history currently remains encrypted in the database. Scheduled-file digests are limited to 256 MiB; physical sharing/digest mutation and target-change scenarios still need acceptance tests. File contents and conditions can change after a check; immutable file snapshots are not yet implemented.
- Bundled English STT/TTS and speaker embeddings are implemented. Three-sample enrollment is gated by Android device credential. Speaker similarity is not a calibrated probability or proof against replay/impersonation. Physical-device/OEM/liveness and microphone quality acceptance remain pending.
- Personalized wake templates have synthetic tests; real custom wake-name false-accept/false-reject and short-utterance speaker tests remain required. Verified follow-up and opt-in low-risk voice execution are wired, but physical end-to-end owner-wake/command acceptance and barge-in while speaking remain pending.
- Background wake uses a user-started microphone foreground service with stop notification and profile/permission checks. It pauses while AIVORA is visible; default Assistant uses the system session path and otherwise posts a notification. Active background microphone/owner-wake behavior, OEM power restrictions, reboots and long-duration battery behavior still require verification. No automatic microphone restart after process death.
- RecognitionService protocol/discovery and supplied-PCM transcription are tested through Android's SpeechRecognizer client. Real microphone recognition-provider lifecycle/attribution across the target Android versions remains pending. Saving a name does not replace an enrolled wake profile until new enrollment succeeds.
- Calls/messages/alarms/files/connectivity use legitimate system UI; external completion is not claimed. Contacts resolve exact names or ask which number, and execution rechecks the selected number. Local document indexing requires owner-selected persisted read grants and supports Android local storage providers only. Sharing still requires choosing the recipient and sending in the external app; physical credential-screen and chooser tests remain pending.
- Room v2 preserves v1 memory and adds encrypted structured records, protected HMAC word/prefix FTS and encrypted document metadata. Explicit taught phrases support up to 20 supported actions separated by 'then'; each invocation is parsed and policy checked again. Context-dependent contact/file commands cannot currently be stored as routines. Project-scoped file vocabulary supports explicit teaching, correction and stable selected-file references. Unresolved sharing accepts the documented combined recipient/file explanation with a selected project; broader free-form clarification, entity relationships, inferred habits and consolidation remain pending. Revoked folder metadata remains encrypted but hidden until cleanup; content changes are not immutable snapshots.
- API 35 emulator coverage only; physical microphone, speaker quality, battery, OEM, APIs 29/31/34/36/37 and release signing remain pending. Native, corpus and dictionary license-notice inventory remains incomplete.
- Gradle connected tests encounter a UTP/Dagger tooling error. Direct ADB instrumentation works; use tools/Test-Android.ps1. Do not mistake adb's exit code for a passing test suite.



- YouTube accessibility fallback is optional and strictly scoped to known English play/pause controls. Screens with password fields, ambiguous/changed/unknown controls, or a tree exceeding 500 nodes, depth 24 or a 500 ms inspection budget are rejected. Descriptions are bounded and never logged/saved; no screen text is collected. Actual service binding and wrong-app rejection passed on API35, and selector resource IDs/labels were inspected in the installed YouTube APK. Positive clicks/playback, interruption/revocation, translated layouts and updated app versions remain acceptance work. No accessibility messaging/payment adapter exists yet.



- WhatsApp/Business named drafts use supported click-to-chat links with exact confirmed app/recipient/body. Full international numbers are required and no alternate app/browser fallback is attempted. Installed/account-ready conversation population, automated authorized Send and delivery/read verification remain unfinished. YouTube accessibility permissions do not enable WhatsApp control. No real recipient was messaged during tests.

- Spoken approval is opt-in and requires owner enrollment plus a verified reply. It reads complete bounded plans before capture and accepts an explicit confirmation phrase; bare yes is ambiguous. Complete review prompts may contain up to1200 characters; larger prompts require on-screen review or shorter requests. The original deadline includes speech, and expiry/replacement during speech prevents reply capture. High-risk Android credential authentication still uses the real system prompt. Physical prompt-echo, spoofing, short-reply recognition and interruption acceptance remain unverified; emulator gate/ViewModel tests are not end-to-end voice evidence.

- Verified opted-in sensitive voice requests now automatically open Android's device-credential prompt; actual credential entry still follows Android's system UI and is not voice authentication. Successful callbacks wait until AIVORA resumes before returning to confirmation. Physical credential completion, cancellation during an active prompt, Android11+ credential-prompt lifecycle and OEM acceptance need explicit device tests. Unit launch-gate and ordinary API35 regression tests do not prove these system-authentication paths.

- Repeated foreground wake now has an explicit `Keep listening while open` control. Control-loop tests and API35 real recording-configuration/lease tests cover waiting, pause, resume and stop. They do not establish physical wake detection, speaker/command recognition, prompt echo, liveness, battery use or complete hands-free app workflows. The mode is runtime-only, pauses when not resumed/visible/unlocked or during device authentication, and stops on explicit Stop/Cancel, enrollment/profile changes or hands-free opt-out. Process restart requires a new explicit start. Background operation still follows Android's separate foreground-service and Assistant-role rules.

- Spoken contact/file choices now support explicit numbers/ordinals, three-entry readback pages and capture-bound list tokens. Number words/ordinals one through twenty and numeric list replies are supported; broader descriptive answers such as a location or relationship remain incomplete. The two-minute deadline includes paging; expired lists require repeating the complete request. Entire pages exceeding1200 description characters need a narrower request or on-screen review. Physical speech/owner verification for short replies, echo, large lists, languages/OEMs and complete touchless clarification sequences remain unverified. Injected verified-command Android tests establish routing, not acoustic recognition. Resulting messages/shares still have the existing external-app completion limitations.

- Opted-in confirmed Wi-Fi actions support the known English SystemUI Internet dialog and the API30 Settings Internet Connectivity panel. Native off/on, radio state and panel dismissal/return are verified separately on API30/API35 emulators. The API35 task probe separately proves refusal while unvalidated and resumption after harness-restored mobile data; it does not establish Wi-Fi internet, physical spoken approval or playback. Production single-ready-default-SIM mobile-data switching has separate API30/API35 emulator evidence; real credential/voice and physical SIM/OEM acceptance remain pending. Network/password selection, silent APIs, restoration and physical/OEM/locale coverage remain incomplete. Generic Settings pages are not a fallback. Settings service scope is added only on API30; no gestures, tool relabeling or continuous screen capture is added.

- Online-task spoken approval now uses a single-use captured original task token/plan/source/deadline and complete short-task readback. Complete connection prompts over1200 characters require on-screen review or a shorter repeated task; the one-minute deadline includes speech/capture. The explicit emulator probe injects verified command results to test stale/fresh reply routing; it is not a live speaker/microphone test. Connection approval remains separate from action confirmation, Android authentication, validated-network availability and external completion.

- Mobile-data control currently supports one ready default subscription with phone-state permission and a separate opt-in. Multiple/changed/unavailable SIMs, roaming enablement and unknown/localized controls are refused. There is no automatic restoration or SIM switching. The separate API35 probe verifies native setting changes and validated cellular task resumption; injected authentication does not prove real credential or acoustic approval. Mobile-data routines/multi-action requests remain unsupported.

- Installation baseline is Android 11/API30 across device models. POCO X8 Pro Max and OPPO K13 Turbo are owner test priorities, with firmware unknown and no physical verification. Current emulator evidence does not establish all-device compatibility.

- Duration number words are supported for relative reminders/actions and recurring intervals, with existing limits. Compound duration units remain unfinished; use one duration unit. Clock fields now support exact English hours/minutes and AM/PM; ambiguous expressions require clarification, and idioms such as half past seven are not yet supported. Parser tests do not establish acoustic recognition or delivery timing.

- Typed merchant UPI-link review/handoff is available, separately from payment-app automation. Actual Google Pay/PhonePe acceptance, bank-resolved identity, transfer and PSP settlement verification remain unproven. No Pay click, PIN handling, verified-success state or automatic retry exists. Named personal recipients, QR import and complete spoken payment reviews remain unfinished; long reviews use full on-screen confirmation. Stored checkout links cannot be scheduled or reused as taught routines.

- API30 emulator baseline now has39 applicable passing tests, with2 API33-only provider tests excluded. This does not verify physical/OEM/legacy Internet-panel switching or all-device compatibility.

- Legacy mobile-data controls now match the exact API30 Mobile data row and independently read SIM summary; multiple/changed/unready subscriptions, roaming enable and unknown dialogs remain unsupported. Explicit API30/API35 probes use an injected credential callback and do not prove physical authentication or complete hands-free operation.

- Payment readback now spells supplied fields character by character and preserves case, digits, spaces and punctuation. Only printable ASCII has a complete supported spelling; other character sets and oversized expanded prompts require UI review. Amounts use Indian rupees plus hundredths of a rupee because the bundled lexicon lacks paise. Native PCM and lexicon checks do not establish real owner comprehension/approval or bank/app acceptance.

- Optional direct calling now requests an ordinary international call through system Telecom after Android authentication and exact confirmation. Only one verified ready default voice SIM/account, no roaming and no existing call are supported. No real carrier connection/answer, device credential or physical spoken request is verified. Local-number country inference, multi-SIM/VoIP/emergency, incoming-call management and end-call voice commands remain unfinished. The existing dialer-only path remains default. Tests use isolated emulator modems, not calls to real people.

- Direct mode now preserves reviewed dialer fallback for short/local numbers, unavailable permissions/accounts and mixed plans. This is not automatic emergency/service calling or country inference. Native named-contact mutation tests establish stale-number refusal and fresh emulated routing, not physical voice, credentials or carrier identity/answer.

- Explicit speakerphone requests are implemented, with reported-route emulator checks on API30/API35. Production reports a request, not verified physical audio. Bluetooth/wired/OEM behavior, physical audibility and remote call connection remain pending. Dialer-only fallback requires choosing speakerphone in the dialer.
