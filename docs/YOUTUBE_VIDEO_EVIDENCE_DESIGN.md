# YouTube explicit-video playback evidence

Existing explicit YouTube video actions carry an exact eleven-character video ID. Preserve that action/codec and normal internet/authorization flow. After package-pinned app launch, observe public media-session evidence for a bounded ten seconds. Report session-playing success only with one YouTube session, STATE_PLAYING, and an explicit matching media ID or strict YouTube watch URI. Conflicting identity fields or another YouTube session refuse success; titles/artists, a changed button, intent acceptance and an unrelated playing session are insufficient. Missing notification access remains a handoff, never a new permission grant or silent settings change.

Session evidence means what YouTube reports, not physical audibility, ad-free content or completed viewing. Keep identifiers transient, do not save media metadata to memory/logs. Cancellation stops observation; locking during observation prevents a verified-success return. Unsupported/missing app retains existing browser handoff. Broad query result selection remains separate work.

Validation scope: pure evidence tests cover exact matching ID/URI plus playing state, paused/missing identities, unrelated/multiple sessions, conflicting or opaque identity fields, duplicate query parameters, fragments, credentials, foreign hosts and encoded/extra URL fields. Build and ordinary regression results do not prove YouTube exposes compatible metadata or successfully plays content. A live emulator launch attempt was rejected by automatic approval review with only `blocked by policy`; it was not retried through another mechanism. Real-app positive acceptance remains pending.
