# Direct SMS

Default-off direct SMS upgrades only a single explicit SMS draft with canonical international recipient and body at most160UTF16 characters, when SEND_SMS and READ_PHONE_STATE plus one ready, non-roaming complete-active default SMS subscription can be verified. Preserve existing draft review otherwise, before authorization. WhatsApp/Business are unaffected. Exact typed SendSms is HIGH risk and standalone; show recipient/body/SIM/carrier charges and require device authentication then fresh confirmation. Do not save direct sends in schedules or routines.

Execution rechecks opt-in, permissions, unlocked foreground, contact number and complete-active default SMS subscription after settings suspension and immediately before send. SmsManager.divideMessage must return exactly the full original single fragment; no truncation, multipart sends, inferred country codes or silent fallback after approval. Use subscription-pinned public SmsManager. PendingIntent targets a non-exported receiver with unique nonce, immutable/one-shot identity, registered before effect. Only its sent result can establish Android-reported submission. Timeout or interrupted process/cancellation after request means uncertain; do not retry. No delivery receipt claim, durable sent-message ledger, automatic retry, multi-SIM selection or physical carrier acceptance is established by this increment. Audit Started persists before effect and contains metadata only. Transient callback registrations/handles are removed on completion/cancellation; no message body enters callback intents or logs.

Verification: planner preservation/upgrade, validation/codec/readback, policy before effects, nonce result/replay handling, default-off permission refusal on native Android, builds/lint/regressions. Emulator/physical actual submission and delivery remain explicit acceptance tasks; ordinary tests must never send messages.

## Explicit Android framework failure acceptance

`tools/Test-SmsFramework.ps1 -Serial <isolated AIVORA emulator>` builds and invokes excluded SmsFrameworkProbe. Host requires known AVD name and home registration; native probe requires qemu, ranchu/goldfish, x86_64 and API30/35. Temporary SEND_SMS/READ_PHONE_STATE grants and out-of-service virtual modem registration are test fixtures, not production permission/radio bypasses. Script finally restores previous grants and home registration. A powered-off-radio variant was refused at the existing SIM-readiness guard; it was not weakened. The final probe uses a ready SIM with virtual voice/data registration unregistered and verifies OUT_OF_SERVICE before request.

Through the real ViewModel, the fixture obtains exact SendSms review, injects a credential result, confirms separately, calls production SmsManager, receives real Android RESULT_ERROR_NO_SERVICE (4) through the private receiver, observes durable FAILED_REPORTED and a truthful failure response, then asks SMS status and verifies no new request. The recipient is a fictional number on an isolated virtual modem; no message is submitted/delivered and no physical/PSTN acceptance is claimed. This is actual framework failure routing, distinct from the synthetic callback journal test. AIVORA journal fixture row is deleted; the system messaging app may retain its own failed fixture record.

Positive modem/carrier submission, delivery, real credential/spoken approval, full process-death/cold-start callback acceptance and OEM/multi-SIM behavior remain unfinished.
