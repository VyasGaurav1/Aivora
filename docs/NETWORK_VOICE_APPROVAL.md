# Spoken online-task approval

An online request awaiting connection permission has a NetworkReview containing its random token, immutable original plan, original command source and monotonic expiry. VoiceNetworkGate records that review before manual command/reply capture, or after a verified wake before automatic command capture. A spoken `connect for this task` consumes the binding once only for VERIFIED_VOICE and only if the current token, plan ID, original source and deadline still match. Expired, replaced, canceled, unverified or replayed replies cannot approve another task.

New ordinary commands invalidate the pending connection synchronously at submission, before joining older work. Connection replies are checked before canceling/interruption of existing command work; a stale connection reply therefore does not discard a newer pending action review. A valid reply still passes its captured token to ConnectivityOrchestrator, which independently checks current identity and expiry. Typed foreground replies and the token-bound dialog button remain explicit owner input. No approval source is read from serialized action/model data.

The Internet dialog shows the full original task description in a scrollable review. `Read task and reply by voice` reads complete short descriptions, then uses the same local owner-verification/STT pipeline for a bounded reply. Verified opted-in requests can start that readback automatically. Descriptions longer than300 characters require on-screen review or a shorter repeated task; they are not truncated into spoken approval. The one-minute deadline is unchanged. Capture preparation joins a task already presenting a confirmation/contact/file/network question instead of canceling that task; it then arms the relevant reply bindings.

Permission to connect remains separate from permission to execute. A Wi-Fi helper still requires its own typed-action confirmation and opt-in. Original actions still use the original registry/provenance, validated connectivity, foreground/lock checks and any required target review/authentication. Connection approval never grants a device credential or establishes that a message was sent or a payment completed.

Pure tests cover identity/source/deadline/replay, replacement without approval, immutable original plan, expiry and cancellation. Ordinary API35 regression checks that a connection reply with no matching online task preserves a pending brightness review. The explicit isolated-emulator WifiSettingsProbe injects verified-command grants at the production callback boundary: an old captured task is replaced, its connection reply is refused without changing the replacement task or radio, and a fresh captured reply reaches Wi-Fi confirmation. Real radio toggling and separate validated-network/original-task resume checks continue afterward. These tests do not prove acoustic owner recognition, real spoken approval, Wi-Fi-provided internet, AIVORA mobile-data switching or video playback. Physical/OEM/short-reply/echo/interruption and long-review acceptance remain unfinished.
