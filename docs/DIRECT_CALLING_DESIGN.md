# Direct cellular calling

Opt-in direct calling upgrades resolved call requests from dialer review to a typed HIGH-risk PlaceCall action. CALL_PHONE and READ_PHONE_STATE remain runtime permissions; real Android authentication then exact confirmation gate execution. Default-off keeps existing dialer-only behavior. Initial direct calls require a full canonical international number, one complete active ready non-opportunistic default voice SIM, one enabled SIM Telecom account mapped to that public subscription ID, no roaming and no existing call. Caller subscription metadata is bound before review and rechecked immediately before requesting the call. No ICCID/IMSI/account-handle string is decoded, logged or stored; the framework handle is an opaque transient routing capability.

Android [TelecomManager.placeCall](https://developer.android.com/reference/android/telecom/TelecomManager#placeCall(android.net.Uri,%20android.os.Bundle)) sends the request through system Telecom using an explicit phone account. [TelephonyManager.createForPhoneAccountHandle](https://developer.android.com/reference/android/telephony/TelephonyManager#createForPhoneAccountHandle(android.telecom.PhoneAccountHandle)) maps that account to its public subscription. No implicit third-party call intent, MMI/USSD, emergency call, automatic retry, new SIM choice or lock bypass. Named contacts recheck their current number. Returning from placeCall establishes only a request; use REQUIRES_USER_INTERACTION and never claim connection/answer without authoritative observation. Carrier/Android restrictions may refuse the request.

Scheduled calls retain exact caller metadata and fresh due-time review. Learned explicit-number commands bind anew at invocation; taught unresolved named contacts retain existing limitations. Calls must be reviewed alone. Full multi-SIM/VoIP/roaming, contact country inference, emergency workflows, real authentication/acoustic approval and physical carrier connection remain unfinished. Tests must never place real calls to people: policy/codec tests use mocks; ordinary Android tests exercise denial before Telecom; any native call probe must be explicitly isolated to the known emulator image and end its simulated call.

API35 account-detail lookup required READ_PHONE_NUMBERS in the first probe. Production avoids that lookup: callCapablePhoneAccounts supplies enabled handles, and createForPhoneAccountHandle must map the sole handle to the exact public voice subscription. Both SDK probes passed without subscriber-number access. The default-off permission/setup controls are implemented. Native probes use injected credential callbacks and the known emulator modems; they do not prove actual Android credentials, carrier connection or remote answer.


Before authorization, unavailable direct-call permissions/selection, short/local numbers and mixed plans retain the exact original Dial plan. This is an explicit reviewed dialer handoff, with no country inference or automatic call. After a PlaceCall is confirmed, changed contacts/accounts or other failed guards refuse; they never silently change it into another action. A second contact recheck follows the settings suspension. Named-contact native probes verified actual Android provider mutation refusal and a fresh request before emulated Telecom, with fixtures removed afterward.

Explicit speakerphone requests now bind into the reviewed/stored action and pass the system Telecom speakerphone extra. Default-audio records remain unchanged. See SPEAKERPHONE_CALLING_DESIGN.md for route observation and limitations.
