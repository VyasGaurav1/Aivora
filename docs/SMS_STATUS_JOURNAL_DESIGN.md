# Persistent SMS submission status

Use separate fixed-name aivora_sms.db Room1 journal. Before SmsManager is invoked, commit a unique REQUESTED record with encrypted versioned SendSms payload, bound by record-specific AEAD associated data. This records an authorized explicit action, not learned conversation memory; private mode does not disable necessary request status. REQUESTED and UNKNOWN mean submission is uncertain, never unsent, failed or safe to retry. No startup/reboot resend code exists.

A private sent PendingIntent retains its durable journal ID. Receiver goAsync work commits first reported sent result before resolving the optional in-process observer. First terminal result wins: SUBMITTED means Android-reported submission only, FAILED_REPORTED means Android reported failure; neither verifies recipient delivery. A timed-out or canceled observer is removed, but an attempted request's one-shot PendingIntent remains valid for a late callback, including after process recreation. UNKNOWN can accept that late result; stale/conflicting/replayed results cannot overwrite terminal state. If the fresh pre-effect guards fail after journal creation, NOT_REQUESTED records that the SDK was not invoked. Process death between commit and request remains uncertain, conservatively.

The voice/text commands `SMS status`, `what is the status of my last SMS`, and `did my last SMS send` report the last request made through AIVORA, exact recipient/message, and qualified status. They do not inspect other apps' SMS, retry or send. Explicitly label journal retention in direct-SMS settings. No body/recipient in broadcasts or logs. Request IDs/state/timestamps are metadata; payload encrypted. History deletion, delivery receipts, multi-part sends, actual modem and physical/OEM acceptance remain separate required work.

Verify Room persistence/reopen, encrypted payload/record-swap rejection, exact status compare-and-set transitions, timeout/late result/replay and NOT_REQUESTED stability, parser commands and regression. Injected callback tests are not real modem submission proof.

Latest-request ordering uses SQLite insertion rowid, not wall-clock timestamp or random UUID order. Tests insert a rolled-back wall-clock timestamp to ensure it still represents the latest inserted request. Query-only change does not alter the Room1 entity schema. Native receiver testing sends a synthetic RESULT_OK PendingIntent without SEND_SMS permission or any SmsManager request; it establishes callback persistence without an observer, not actual cold process restart or modem submission. Separate Room close/reopen verifies retained encrypted data. Global voice/text Cancel routes to the same cancellation helper as the UI; if confirmation execution was an SMS send, it reports that waiting stopped and the request may already be submitted, then directs the owner to SMS status.
