# AIVORA

Offline Android personal assistant under construction. Permanent application ID: `com.chronoit.aivora`. The assistant's configurable name initially defaults to `Aivora`.

Current speech provider: Gnani Prisma v3.0 STT and Timbre v3.0 TTS when an owner key is saved in Settings. Select Automatic for all 10 supported speech languages: Bengali, English (India), Gujarati, Hindi, Kannada, Malayalam, Marathi, Punjabi, Tamil and Telugu. This route requires internet and credits; wake listening streams microphone audio to Gnani until stopped. Transcripts appear after recognized speech segments. Task parsing for reminders and alarms currently uses English. Keys are encrypted on-device and never embedded in the APK. Android system recognition and Indian English/bundled output are used without a Gnani key. Live physical wake/task acceptance remains open.

Current release setup: allow microphone and notification access, choose AIVORA as Android's digital assistant, and play the test greeting in Settings. Replies prefer your phone's downloaded English (India) voice; install it in Android Text-to-speech settings if needed. Tap Start wake listening, keep the phone unlocked on Home, say **Hey Aivora** or **Hey Jarvis**, then pause for the greeting before speaking. No voice enrollment is required for these release phrases. Home and the voice panel display the recognized words as you speak. Say **Goodbye** to end the conversation. Reliable live wake/conversation acceptance is still in progress; see docs/COMPLETION_CHECKLIST.md.

Use JDK 21 and Android SDK 37. Set `ANDROID_HOME` to the SDK directory, then run:

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug assembleRelease lintDebug
```

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`. Install after a successful build using `adb install -r app/build/outputs/apk/debug/app-debug.apk`.

Current scope and remaining capabilities are recorded in PROJECT_STATE.md and KNOWN_LIMITATIONS.md. Voice provides protected owner/wake enrollment, foreground verified follow-up, speech output and a user-started background wake service. Enable hands-free controls explicitly in Settings. Background activation uses Android's selected Assistant session or a notification fallback. Physical owner-wake accuracy, interruption and OEM battery validation remain required; the full specification is unfinished.

Verify bundled speech artifacts with `tools/Verify-Models.ps1`. Run Android integration tests using `tools/Test-Android.ps1 -Serial emulator-5560` (set ANDROID_HOME first). This directly launches instrumentation because this environment's Gradle UTP launcher has a Dagger linkage error. It fails if the actual instrumentation result does not pass.

Personal facts work offline: say `remember that my favourite colour is blue`, then `what is my favourite colour?` or `what about my favourite colour?`. Repeating the explicit remember command with a new value corrects the same subject and keeps the old record historical. Private mode prevents both insertion and replacement. Only explicit current owner facts are used; conflicts ask for a current value, and unknown subjects are not guessed. These answers do not execute remembered text. To delete one subject, say `forget my favourite colour` or `forget what I told you about my favourite colour`. AIVORA reviews the current values and record count, including historical values, then requires device authentication and a separate exact confirmation. Changed facts invalidate that review. This command does not delete other subjects, inferred records, conversation text or backups, and cannot be scheduled or taught as a routine. This is bounded personal-fact recall, not general local reasoning.

Use Files to grant access to local files or folders. Try `find FinalReport.pdf`, then `send it to Rahul`; AIVORA asks about ambiguous references and opens Android's share chooser. Allow contacts in Capabilities for name resolution. To teach a routine, type `when I say usual setup, do volume 30 then pause music`. Repeat that teaching command to correct it, inspect/delete it in Memory, and say `usual setup` to request the actions. Private mode prevents saving new routines.

For project vocabulary, say `use project Atlas`, then `blue one means file FinalReport.pdf`. Select the intended file if several match. In that project, `open file the blue one` or `send Rahul the blue one` reuses the selected file, subject to current access and action policy. Repeat teaching to correct the reference or delete it in Memory. Project selection is working context for the current app session; select it again after restarting. Private mode blocks saving new references.

An unresolved share request can also accept a combined explanation: after `send him the blue one`, reply `Rahul. In this project, blue one means FinalReport.pdf.` within two minutes. AIVORA resolves the file and contact, asks you to choose if needed, learns the file reference unless private mode is on, and requests the normal authentication and sharing confirmation. The project must already be selected. Cancellation or another command discards the pending explanation.

Persistent reminders: `remind me in 10 minutes to stretch`, `remind me every 1 hour to drink water`, `list reminders`, and `cancel reminder <ID>`. Definitions are encrypted in `aivora_tasks.db`; WorkManager supplies approximate delivery and restart recovery. Repeats must be at least 15 minutes apart. Allow notifications; blocked deliveries remain pending rather than being reported as delivered. These explicit task definitions persist independently of private-mode learning. Exact alarms, conditional tasks and scheduled action approval are still under development.

The Reminders tab also creates reminders, lists active tasks, shows notification status and confirms cancellation. Notification permission is independent of starting background voice. If permission is already granted, the notification button opens Android's notification settings so blocked channels can be changed.

Scheduled actions: try `in 10 minutes volume 30` or `tomorrow at 9 send Rahul FinalReport.pdf`. AIVORA resolves the target now and stores an encrypted typed action. When due, it notifies you and waits for review. Use **Review action** in Reminders, say `review due action` to review one task or hear numbered choices when several are due, or `review next due action` for the oldest due action. Say `choose task number two`, `next choices` or `previous choices` to select from the two-minute list. Selection opens review and never executes the task; the saved occurrence is checked again. `review scheduled action <ID>` selects an exact task. Explicit foreground review can prepare a due task even if notification delivery is delayed or blocked. Every saved action requires fresh exact confirmation; sensitive actions still require credentials first. Targets and cancellation are checked again at execution. File contents are SHA-256 checked at scheduling/review/execution (256 MiB maximum); changed files require a new task. Named sharing recipients must resolve uniquely. No action runs from the scheduler worker. Interrupted attempts remain visible with uncertain status and are never retried automatically. Automatic background execution, multi-action recurring plans and broader event triggers remain unfinished.

Conditions can be selected in the Reminders form or prefixed to a timed command: `when charging, remind me in 10 minutes to stretch`, `when online, in 10 minutes open Browser`, or `when charging and on unmetered network, tomorrow at 9 send Rahul FinalReport.pdf`. Conditions apply at or after the saved due time, not instead of the due time. WorkManager waits for them; AIVORA rechecks charging and validated network state before delivery, review and execution. Conditions never enable network connectivity automatically. Explicitly reviewing a due online action can enter the task-bound connection approval flow while offline; charging must already hold. Once connected, every saved condition (including unmetered access), target and exact occurrence is checked before action approval and again before execution. An offline action with a network condition still waits for that condition. Network validation observes Android's reported capabilities and is not a guarantee that a particular website or recipient is reachable.

Recurring actions use `every 1 hour volume 30` or `when charging, every 1 day pause music` (15-minute minimum). Each occurrence waits for a fresh review; it does not inherit a previous occurrence's approval. After a verified result or a system-app handoff, the next due time advances along the original interval, skipping missed occurrences. A handoff does not mean the external action completed. Failed or unverified results pause the series for inspection; cancel it and create a new task after checking the result. Canceling the task stops the entire series. Automatic execution and multi-action recurring routines remain unfinished.

YouTube requests: `search for birds on YouTube`, `play calm music on YouTube`, or `play https://youtu.be/<11-character-video-ID>`. Title requests open search so you can select the intended video; exact supported video links request that video. Search handoffs do not select a search result. Exact video links now observe media-session evidence for up to ten seconds when notification access is available. AIVORA reports session-playing success only for one YouTube session with matching explicit video identity and playing state; missing/conflicting identity remains an unverified handoff. This is reported session state, not physical audibility, ad-free content or completed viewing. Positive real-app playback acceptance for this new path is still pending. Online actions declare their network requirement; offline actions remain independent of connectivity. Settings offers leave unchanged, ask, open Android controls when needed, and request restoration afterward. In standard mode AIVORA cannot silently switch or restore connectivity. An approved task waits up to one minute for validated connectivity and foreground/unlocked AIVORA, then resumes the same plan and provenance through action policy. New commands/cancellation discard it. No background launch or completed-playback claim is inferred. Scheduled YouTube actions automatically save a validated-network requirement.

`pause YouTube` and `resume YouTube` control an existing video. Authorized, package-matched media-session controls are preferred and report success only when YouTube reports the requested playback state. With optional **AIVORA app controls** enabled in Android accessibility settings, a scoped fallback can operate known English play/pause controls. It checks the active package, unique resource ID/description and fresh window before acting, and refuses password screens, ambiguous/unknown controls and truncated trees. A UI-only result remains partial. No arbitrary taps, gestures or payment controls are exposed. Use `app control settings` to open the permission screen. Compatible-device positive playback and version/language coverage remain pending.

For an explicit SMS draft, say `draft SMS to Rahul that Hello` or `draft a text to +12025550123 saying Hello`. This stays a draft even when direct SMS is enabled, including through contact choices, routines and saved actions. Review and sending remain in your messaging app.

Direct SMS is a separate default-off option in Settings. Allow SMS sending and SIM verification in Capabilities, then use `text +12025550123 that Your short message` or resolve a named contact. Eligible single messages receive exact recipient/body/SIM review, device authentication and fresh confirmation before submission. Carrier charges may apply; internet is not required. Unsupported/missing permission, local numbers, longer messages or unavailable SIM selection retain draft-only review before approval. A non-single-part encoding is refused without sending. Android sent-callback success means reported submission, not delivery. Timeout/interruption is uncertain and never retries automatically; check your messaging app before resending. Direct sends are not scheduled or taught routines. AIVORA now retains encrypted recipient/message/status records separately from learned memory, including in private mode. Say `SMS status`, `what is the status of my last SMS`, or `did my last SMS send`. These commands report the latest AIVORA request without sending or retrying. Late sent callbacks can update an uncertain record without a live observer. Actual modem/carrier submission, delivery, full process-death and physical acceptance remain unfinished.

Named messaging drafts: `message Rahul on WhatsApp that I'll be late`, or `message Rahul on WhatsApp Business that Hello`. AIVORA resolves the contact, asks which number when needed, and confirms the exact app/recipient/body before requesting the supported chat draft. Use full international numbers including `+` and country code; missing country codes are not guessed. The selected client must be installed. Drafts use [WhatsApp's supported click-to-chat format](https://faq.whatsapp.com/5913398998672934), with no browser or other-app fallback. AIVORA does not yet press Send or verify WhatsApp delivery; review and send in the app. Full voice sending remains unfinished.

Spoken approval: after owner enrollment and hands-free opt-in, a verified voice request that needs confirmation can read back a short complete plan and listen once for `confirm the action I just reviewed` or `cancel`. `confirm action` and `approve action` are also explicit approvals; a bare `yes` is not. Approval is bound to the token and plan present at recording start, expires with that request, and cannot authenticate a device. Android authentication remains a separate step for sensitive actions. Long plans (over 300 description characters) keep their scrollable on-screen review and confirmation; they are not truncated for spoken approval. Physical short-utterance/echo/spoof/cancellation acceptance remains pending.

Separate emulator probes are excluded from the normal Android suite because they require external state changes. Run `SchedulerRebootProbe` with instrumentation argument `rebootPhase=prepare`, reboot the isolated emulator, then run it with `rebootPhase=verify`; it asserts an increased system boot count and a posted reminder. Run `SchedulerPermissionProbe` with `permissionPhase=denied` after revoking POST_NOTIFICATIONS, then `permissionPhase=restored` after granting it. Reports from the verified runs are in `app/build/reports/scheduler-reboot.txt`, `scheduler-permission-denied.txt`, and `scheduler-permission-restored.txt`. Do not run disruptive probes on a personal device.



Sensitive voice requests: with hands-free controls enabled, a verified request that requires device authentication now opens Android's credential prompt automatically while AIVORA is resumed and unlocked. A successful system result returns to exact-action confirmation; it does not execute the action. Old, canceled, expired or replaced request tokens cannot approve another plan. Destroying or recreating the activity during an active prompt cancels that request rather than replaying it. Android credential entry still requires the system's supported interaction; voice matching does not unlock the phone or replace its credential.


Repeated foreground wake: after enrolling owner and wake profiles and enabling hands-free controls, open Voice and choose `Keep listening while open`. This runtime-only mode returns to lightweight wake listening after requests and spoken replies. It waits during other voice work, command execution and device authentication; it pauses when AIVORA is not resumed or the phone is locked, and can resume when you return. `Stop foreground wake listening`, global Stop/Cancel, enrollment/profile changes or disabling hands-free controls stop it. It does not automatically start after app/process restart. API35 tests observe actual recorder pause/resume/stop and shared-lease release; physical wake/command accuracy, echo, liveness and battery acceptance remain pending. See docs/FOREGROUND_VOICE_DESIGN.md.

Spoken choices: ambiguous contacts/files can now read three numbered options at a time and listen for `the second contact`, `choose contact number two`, or `the first file`. Say `next choices`, `previous choices`, or `read choices` to navigate; numbers remain the original list numbers on every page. A captured reply is bound to that exact list and cannot select from a replacement request. The two-minute deadline still applies. Resolving a choice retains the original message/app/file or schedule and continues through normal confirmation/authentication. Dialogs offer `Read choices and reply` after enrollment and hands-free opt-in. This does not send a message or prove physical voice acceptance. See docs/SPOKEN_CHOICES_DESIGN.md.

Wi-Fi control: enable `Allow supported Wi-Fi settings controls` in Settings and enable AIVORA app controls through Android accessibility settings. `turn Wi-Fi on` or `turn Wi-Fi off` requests a confirmed action through the known Android Internet-panel switch. An approved online task can request the same Wi-Fi-on helper when Wi-Fi is off, then resume its original plan only after validated internet is available and AIVORA resumes. Radio state, panel Done/return and internet validation are checked separately. This does not select networks, enter passwords, switch mobile data or restore connectivity automatically. API35 emulator tests verify real off/on panel controls; the emulator Wi-Fi has no validated internet, so its separate resume test restores mobile connectivity through the test harness. Physical/OEM/layout/language and actual voice acceptance remain pending. See docs/WIFI_CONTROLS_DESIGN.md.

The ordinary Android test script excludes `WifiSettingsProbe` because it changes emulator radios/accessibility temporarily. On the isolated test emulator only, invoke that class with instrumentation argument `wifiProbe=true`. Its final reports are `app/build/reports/wifi-settings-probe.txt` and `wifi-settings-evidence.txt`. It verifies radio controls separately from internet validation; test-harness restoration of mobile connectivity is not a production mobile-data feature.

Spoken connection approval: the Internet dialog now displays the complete pending task and offers `Read task and reply by voice`. For a verified opted-in request, AIVORA can read a complete short task and listen once for `connect for this task` or cancel. The reply is tied to that task's original token/plan/source/deadline and cannot approve a replacement request. New commands invalidate it immediately. No-match replies preserve another pending action review; connection permission still does not confirm or authenticate the original action. Long descriptions over300 characters need on-screen review or a shorter repeated task, and the one-minute deadline is unchanged. See docs/NETWORK_VOICE_APPROVAL.md.

Supported installation baseline: Android 11 (API30) and later, across device models. Physical/OEM acceptance remains in progress.

Mobile data: grant phone-state access in Capabilities and enable the separate mobile-data controls opt-in. Try `turn mobile data on` or `turn mobile data off`. One ready default SIM is required; Android authentication and exact confirmation precede changes. Task-driven connectivity may propose this control when Wi-Fi is unavailable. A verified user setting does not imply internet; task resumption also requires Android-validated connectivity. No automatic restoration or SIM switching is implemented.

Spoken control forms include `turn on mobile data`, `disable Wi-Fi`, `set volume to twenty five percent` and `brightness ninety-nine percent`. Percentage commands accept whole values from zero to one hundred. Connectivity opt-ins and normal policy checks still apply.

Spoken durations also work: `remind me in five minutes to stretch`, `every one hour volume twenty five`, and `when charging, in twenty minutes disable wifi`. Recurring intervals remain at least15minutes; scheduling remains approximate and actions still require fresh review when due. Compound durations currently need one unit, such as `sixty-five minutes`.

Clock times: `alarm seven thirty pm`, `alarm seven oh five am`, and `tomorrow at seven thirty pm volume twenty five`. With no AM/PM, hours use24hour time. Ambiguous spoken forms require clarification; use an explicit clock such as `23:00`. Alarm requests retain their normal confirmation and Android alarm-app handoff.

Payment-link review (incomplete integration): `review payment <complete merchant UPI link> using Google Pay` or `using PhonePe`. INR requests must include exact pa/pn/mc/tr/am/cu fields; optional tn/url are reviewed too. AIVORA does not invent merchant metadata or verify bank identity. Android authentication and exact confirmation precede a package-pinned request handoff. Review the bank-resolved recipient and amount in the payment app. No transfer, payment-app acceptance or completion has been verified. Complete spoken prompts support up to1200 characters; larger prompts require on-screen approval. Expiry during speech aborts reply capture. Saved merchant-link routines/schedules are refused. See docs/PAYMENT_HANDOFF_DESIGN.md.

Android11 emulator acceptance:39 applicable tests passed on API30;41 passed on API35. API33-only recognition-provider tests are excluded from API30 counts. Physical POCO/OPPO, OEM, actual voice and payment acceptance remain pending.

Wi-Fi controls now include the known Android11/API30 Settings Internet Connectivity panel as well as the newer tested SystemUI dialog. Separate emulator probes verified real radio off/on and return to AIVORA on API30/API35. Unknown screens/locales and generic Settings pages remain unsupported; physical/OEM acceptance is pending.

Single-default-SIM mobile-data controls also support the tested Android11/API30 Internet Connectivity panel. Native API30/API35 probes verified user-setting off/on and validated cellular task resumption after injected authentication and exact confirmation. Real credential/voice, multiple SIMs and physical/OEM acceptance remain pending.

Action and connectivity reviews use complete action descriptions, with payment fields explicitly spelled, and a1200character complete-prompt budget. Stopped, superseded or refused speech output is incomplete; expired/replaced reviews do not proceed to voice reply capture. Confirmation deadlines remain unchanged. These checks do not establish physical hearing, recognition or approval.

Payment spoken reviews preserve each printable ASCII character using phonetic letter names, capital markers, digit words and punctuation names. Amounts use exact Indian rupees plus hundredths of a rupee. Unsupported character sets and expanded prompts beyond the budget require full UI review; physical comprehension and payment acceptance remain unverified.

Direct calling: allow phone-call placement and SIM/calling verification in Capabilities, then enable **Place confirmed phone calls** in Settings. `call +12025550123` or an unambiguous contact with a full international number requests Android authentication and exact confirmation before system Telecom. One ready default voice SIM/account is required; roaming, another active call and ambiguous accounts refuse. With the option off, calls retain the dialer-only behavior. Returning from Telecom is only a request, not verified connection or answer. Native isolated-emulator probes passed on API30/API35; physical calling and spoken approval remain pending.

Direct-call fallback: short/local numbers or unavailable direct-call permission/account verification retain a confirmed **Open dialer** action. The app does not infer country codes or silently change an already-confirmed direct call. Named-contact mutation refusal and fresh-request emulator routing are verified; physical calling remains pending.

Speaker calls: `call Mom on speaker` or `call +12025550123 on speakerphone`. The explicit route request survives contact choices and appears in the exact confirmation. Direct mode asks Telecom for speakerphone; fallback opens the dialer and instructs manual speaker selection. API30/API35 emulator probes observed reported speaker routing; physical audibility and carrier connection remain unverified.










Short general questions can use the bundled offline reasoning model. Try `What is two plus two?` with **Offline question answers** enabled in Settings. The app checks memory before loading the model. The first question also needs space for a verified private copy of the 429 MB model. Generated explanations are labeled unverified. Phone commands and personal-fact answers continue through their dedicated paths. The model is released when the answer finishes or is canceled. [Backend design and provenance](docs/LOCAL_REASONING_DESIGN.md).

Say `check permissions` to hear which features need Android access. Say `open app permissions` to open AIVORA's app details and select Permissions. `App control settings` and `notification access settings` open their separate Android controls.

Say `open brightness permission` to review AIVORA's Modify system settings access. The permission scan reports direct Do Not Disturb control and exact reminder scheduling as unavailable. Clock alarms use the Android clock app.

To reply from a current notification, say `reply to WhatsApp notification from Priya saying I'll be there at 6` or use `WhatsApp Business` in the same command. Use the conversation title shown in the notification. AIVORA needs notification access, a single matching notification with an inline reply action, internet, Android authentication, and your confirmation of the exact text. The reply expires if the notification changes or the review takes more than two minutes. The result reports submission to the app and leaves delivery unverified. [Android inline replies](https://developer.android.com/develop/ui/compose/notifications/create-notification#reply-action)

Say `list WhatsApp reply notifications` or `list WhatsApp Business reply notifications` to hear up to five recent conversation titles eligible for replies. Use the title in the reply command above.

Say `YouTube status` or `is YouTube playing` to hear the state reported by the current YouTube media session. Notification access is required. AIVORA reports when it cannot verify the state. Pause and resume verification follows the media session that received the command.
